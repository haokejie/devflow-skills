# Codex 全局偏好

## 协作与实现

- 优先遵循用户明确的语言要求，否则沿用当前对话的主要语言；技术名词保留原文，已有项目文档保留其语言。直接给结论、关键改动、验证和必要风险，避免复述执行过程。
- 明确任务直接推进到可用结果；不清楚且无法合理判断时再问。沿用本轮及此前已明确的授权，不重复确认。
- 环境、文件、代码、日志、版本、计算和数据转换先用工具核实。搜索优先 `rg`；确定性转换用 CLI、Node 或 Python，不靠猜测。
- 遵循用户指定的修改位置和实现路径。若与事实冲突或无法实现目标，先说明证据并询问，不静默换方案。
- 优先从根因修改现有实现，清理被替代的代码和残留引用；必要的类型、导出、配置和验证一起处理，不做无关重构。
- 沿用项目工具链、目录和命名；同一职责保留一个权威实现。确需兼容双路径时说明适用范围和删除条件。
- 不用多层 fallback、字段替代、无依据的默认值或异常吞噬掩盖契约错误；必要兜底应有明确依据。
- 避免嵌套三元表达式；多分支使用 `if/else`、提前返回或 `switch`。

## 授权边界

- 未在当前任务中获得授权的破坏性操作、生产配置修改、新依赖、大范围迁移或公共 API 变更，先说明具体影响再问；按下节约定保存已授权的本地私有信息无需重复询问。
- 不主动提交、推送、变基或重置，除非用户明确要求；生成提交信息不等于执行提交。提交遵循项目配置，没有约定时使用 Conventional Commits。
- 子 agent 仅在用户明确要求，或任务规模明显超出单 agent 上下文时考虑；还须同时满足边界清楚、写入范围互不重叠、结果不阻塞当前步骤且收益明确。普通查询、少量文件修改和连续浏览器交互不委派。
- 环境或工具不可用且无法继续时，说明具体失败证据并询问替代方式；不要凭工具名称或旧路径缺失推断能力不可用。

## 项目规范与记录

- 项目开发规范默认在根目录 `CONVENTIONS.md`；项目已明确指定其他规范入口时沿用。涉及相关代码或配置前读取适用的项目 `AGENTS.md` 与规范。
- 项目 `AGENTS.md` 保留简短的规范入口和必要的 agent 操作说明；项目开发约定只在规范正文维护，任务文档只引用，不复制。
- 开发过程中，本次改动改变已记录的稳定约定、目录、命令或接口模式时，同步更新规范相关段落，无需另等“更新规范”指令。提交前再检查相关规范是否遗漏；无实际变化不刷新日期或重写全文。
- 用户明确约束不能因为源码存在违例而被自动改掉；源码、配置和运行结果用于校准描述性事实。临时实现、单次故障和推测不写成长期约定。
- 未建立规范时按现有源码和配置工作，不强制初始化。旧项目可直接检查 `.codex/project-conventions.md`；需要迁移或整理时使用 `project-conventions`，不同时维护新旧两份正文。
- 共享规范属于项目交付，相关变更应随代码进入用户授权的提交；私有信息使用下节的独立位置。普通开发不因存在 `.task` 就创建或更新任务记录。

## 本地私有信息

- 用户提供并授权保存的账号、密码、token、密钥和本地联调信息可以在本机持久化。沿用项目已有私有配置位置；没有时默认 `.codex/local.md`，记录用途和适用环境。保存授权不扩展凭证的使用范围或生产操作权限。
- 写入真实值前确保目标未被 Git 跟踪或暂存，并被明确忽略：使用 `git ls-files --error-unmatch -- <path>` 和 `git check-ignore -q -- <path>` 核实，定位忽略来源再用 `-v`。必要时先添加精确的忽略规则，再复查；不要为隐藏私有内容而忽略整个共享文档目录。
- 目标已被跟踪时，改用未跟踪且已忽略的私有位置；不要把 `.gitignore` 当作已跟踪文件的保护，也不要擅自改写 Git 历史。若必须改变已跟踪文件的用途或处理历史泄漏，再说明影响并确认。
- 非 Git 目录也将私有路径列入 `.gitignore`，避免未来初始化时误收录；提交前仍须检查实际暂存内容。
- 共享规范、项目 `AGENTS.md`、任务记录和示例只写配置键、用途与存储入口。真实值不进入提交、PR、共享报告或无必要的终端输出；本地文件按需读取，不全量展示。
- 未经要求，不主动搜集或从日志、网页中提取凭证。客户附件与原始日志放仓库外临时位置，任务记录只留必要结论和路径。

## 验证与浏览器

- 先定位再修改；按风险执行最小必要验证，优先已有测试、typecheck、lint 或 smoke test。测试验证行为与契约，不镜像实现；不为低影响改动机械新增测试或跑全量任务。
- 检查最终 diff 和废弃引用，移除临时日志与断点；不弱化断言、盲目更新 snapshot 或用无依据重试掩盖失败。区分本次失败与既有失败。
- 先确定交付载体。会话内可视化使用对应会话能力并在同轮内嵌交付；内部 HTML 或 localhost 不能替代结果，未要求预览时不为验证打开可见标签页。
- 先确定目标浏览器：明确指定 Edge、Chrome、用户浏览器，或依赖其登录态、现有标签页与扩展时，使用对应浏览器并优先复用目标标签页；否则网页操作和前端验收默认使用 Codex 内置 Browser。
- 浏览器接管优先通过对应浏览器插件或扩展连接。先检查当前会话可用的插件能力，必要时使用工具发现入口，并按当前插件说明或 Bootstrap 初始化；不因通用 Computer Use 工具已可用就跳过插件，也不使用旧缓存脚本代替当前入口。
- 按实际连接方式判断能力，不仅凭工具名：若插件明确通过统一工具提供浏览器连接，可按其文档使用浏览器 API；桌面截图、坐标点击等通用 Computer Use 操作作为备用。插件缺失、未连接或实际失败时说明证据，沿用已有备用授权；没有授权时先询问，不静默改用桌面接管、其他浏览器或独立 Playwright。
- CDP 默认全局授权，允许通过当前工具支持的 CDP 入口连接、观察和调试目标浏览器，无需再次请求 CDP 使用权限；该授权不改变插件优先顺序，也不绕过工具限制。
- 调试业务 API 参数、响应或完整请求清单时优先项目请求日志；CDP 用于观察实际网络链路。按当前 API 启用 Network、记录事件 cursor 后再触发动作，分批读取；历史缺失或 `truncated` 结果不能当作完整清单。
- Three.js、canvas、动画等像素断言或跨视口自动校验可补充 Playwright；页面操作与观察仍沿用已选定的浏览器连接。普通页面不重复做等价验证。
- 接口、服务状态、静态构建等不需要页面状态的任务优先 CLI，不默认打开浏览器。
- 最终用一行说明实际验证方式；未验证时说明原因。本地文件引用使用绝对路径与相关行号。

## 专项偏好

- 禅道：只给 Bug 编号或要求分析时只读，不改代码或状态；明确要求修复才实施。带图片、截图、附件或 `fileID` 时先查看再下结论，下载到仓库外临时目录，例如 `/tmp/zentao-mcp/bug-1234/`。
- 持久 JavaScript 环境：临时变量放块级作用域；跨调用状态放有任务前缀的 `globalThis` 属性，避免重复声明顶层 `let` / `const`。
- Go 使用 `asdf` 管理；执行前用 `asdf current golang` 和 `go version` 核实，不绕过到 Homebrew Go。升级时同步检查项目 `.tool-versions`、`go.work` 与各模块 `go.mod`。
