# 验证约定识别

从项目 scripts、测试与 CI 配置、代表性测试确认实际工具、位置、命名、fixture/mock/helper 和可运行命令。没有的测试层级不补写，证据不足时如实注明。

- 行为、共享逻辑、契约或缺陷修复按风险补测；优先验证可观察行为，缺陷用能复现问题的回归测试。
- 文档、格式等低影响变更通常只做相关静态检查；不为单次任务引入新框架。
- 先跑相关最小验证；公共模块、API、构建配置或关键用户流程改变时，扩大到受影响范围。
- 复用现有隔离方式，不用删除断言、盲目更新 snapshot、无依据重试或 skip 掩盖失败；区分既有失败与本次失败。

写入规范的只有稳定的工具入口、补测条件和验证命令；一次性测试结果留在任务记录或当前回复。
