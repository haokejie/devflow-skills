# 前端与 UI 约定识别

## 工程组织

查看路由入口、代表性相邻页面与公共组件，提炼模块组织、请求封装、类型、状态、权限和 i18n 的实际入口。需要有重复实践或明确指令支持，不把单页写法提升为通用规则。

例如项目稳定采用 `index.vue + data.ts` 时，可记录：页面负责状态和交互，描述性表格列、表单 schema 与选项放在 `data.ts`。纯展示页、轻量配置或特殊交互仍按复杂度判断，不为统一外形强制拆分。

复用目录、composable 和 store 以当前项目为准；不因示例存在而创建。接口字段以实际契约校准，不用字段替代或默认值掩盖差异。

## UI 与交互

先读取已有设计文档、用户确认的设计要求及相关设计稿，再查看主题变量、组件库配置、公共组件和代表性页面。记录依据与作用域；未经确认的方案、单页特例与历史违例不提升为共享规范。设计要求与实现冲突时指出差异，不自动将规范改成现状。

按项目实际需要提炼，以下不是必填清单：

- 视觉基础：颜色、字体、间距、圆角等设计变量的来源、语义和用法；具体数值引用代码中的权威定义，不重复抄写。
- 组件复用：组件库、业务组件及适用场景，哪些情况可扩展或例外；已有组件文档只引用。
- 布局与交互：页面布局、响应式、表单校验、弹窗及加载、空、错误、成功状态的稳定模式。
- 可访问性与验证：项目已确认的键盘操作、焦点、对比度等要求，以及实际可用的预览或检查入口；缺项可作为建议，不冒充既有约定。

用户批准修改共享设计约定，或稳定实践改变了已记录的描述性事实时，只更新其唯一维护位置。普通页面开发、恢复规范的样式修复和单页例外不要求同步改写全局设计约定。没有规范时沿用已确认要求和现有稳定模式，证据不足的内容保持为待确认项。

整理文档可做引用与来源检查；声称页面符合设计时，应按改动范围检查实际渲染和交互，不能只凭样式源码或构建通过下结论。单次截图与验收结果留在任务记录或当前回复，不堆进长期规范。
