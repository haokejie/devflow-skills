# 设计方案

用一份方案说明和必要的设计资料保存开发依据，供多个任务与会话引用。回复和文档语言遵循用户与项目约定，文件名与调用 ID 保持不变。

## 按意图工作

- 整理或更新设计：根据用户提供的图纸、原型与说明维护方案，不因整理设计实施业务代码或创建任务记录。
- 按设计开发：读取已有方案与相关图纸，结合项目规范实施已授权的开发；需要记录开发事项时沿用 `task-workflow`。
- 检查设计或清理建议：只读检查，说明缺失资料、设计偏差或废弃候选。明确要求清理才删除。

## 一份方案与必要资料

- 默认使用 `.design/<slug>/SPEC.md`，按 [方案模板](assets/templates/spec.md) 删减内容；需要留存的项目设计图保存到同目录 `assets/` 并写相对链接。资料已有稳定位置或明确设计入口时沿用，不重复复制，不把临时路径当作长期依据。
- `SPEC.md` 只维护适用范围、采用情况、资料链接、设计说明、验收要求和必要的待定问题；任务状态与进度留在 `.task`。沿用已有版本标记，只有需要区分版本时才增加标记，不建立审批或版本目录。
- 根目录 `DESIGN.md` 维护项目通用视觉、组件与交互约定，具体方案只引用。单个页面的约束不自动提升为项目规范。
- `.design` 默认保存本地资料，沿用已有 Git 策略；新建且没有明确共享约定时添加项目级 `/.design/` 忽略规则。客户附件与私密原始资料按项目和全局约定保存在仓库外，只引用必要入口。

## 整理与执行

1. 读取项目指令、相关规范与匹配方案，实际查看有关图片或原型。链接存在不等于已查看；资料不可访问时说明具体缺口，不凭文件名补写设计。
2. 区分已采用的设计、参考资料和待定内容。用户已明确选择或要求照着实施的设计直接沿用，无需重复确认；图片无法表达的交互、状态与约束按已有说明补齐，未明确的内容不写成确定要求。
3. 任务只链接方案、有关图纸与采用版本（有时），不复制设计正文。实施前核对引用仍有效；设计变更时说明影响的任务，未授权的方案变更不静默纳入实现。方案与项目规范冲突时指出差异，不能判断取舍时再询问。
4. 按相关设计检查实际结果，UI 改动查看渲染与交互；构建通过不能替代设计验收。验证结果写入已有任务记录或当前回复，不因验收新增任务记录，也不写进长期设计规范。

## 清理废弃方案

- 用户明确要求清理时，先确认废弃依据，并检查任务、文档和源码中的有效引用；包含隐藏或被忽略的记录，不能仅凭方案时间久或任务已完成判定废弃。
- 只删除已明确废弃且无有效引用的方案及其专属资料。共享图片、引用情况不明或仍被使用的方案保留并说明；有明确替代方案时先更新授权范围内的引用，再删除旧方案。
- 历史记录需要保留原设计依据时保留方案，不批量改成新版本。交付简要列出已清理、因引用保留的内容与未完成事项；提交仍遵循用户授权。
