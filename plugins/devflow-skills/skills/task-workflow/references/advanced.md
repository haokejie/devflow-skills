# 并发与旧记录迁移

仅在相应场景读取，不给普通单任务增加流程。

## 并发与独立任务

- 用户明确要求并行且当前工具允许时，再按任务边界选择子 agent；只有明确要求新建独立 Codex 任务时才调用创建任务能力。不要把“并行”自动解释成创建侧边栏任务。
- 子任务依赖已满足、验收可独立进行，写入范围和共享资源有唯一所有者时才并行。精确允许写入范围只记录在各自 `TASK.md`；重叠文件、lockfile、公共类型、迁移、路由入口等交给前置或集成步骤串行处理。
- 记录实际执行基线。worktree 不会自动继承未提交改动；用工具支持且已获授权的起点，不能假设其他执行器看得到当前工作目录或本地 `.task`。
- 不同用户可见任务的 Git 改动使用独立 worktree；子 agent 遵循当前工具隔离方式和明确的文件所有权。范围不清或接口仍需共同决策时先串行澄清。
- 派发时传递目标、验收、相关事实、允许写入范围、前置完成情况和 Git 授权，避免依赖隐含会话上下文。执行器 ID、hostId/工作目录与子任务关系只记在 `WORKFLOW.md`，按当前等待能力跟踪，不重复创建。
- 协调者负责串行集成和整体验证。提交、merge、cherry-pick 等按实际授权处理；未集成或未验证的并发产出不能宣布整体完成。

## 旧记录迁移

普通只读查询保留旧格式。用户要求继续某个旧事项时，可就地整理该事项；明确要求“迁移旧开发事项”时处理指定范围，未限定则处理当前仓库全部旧记录，不修改业务代码。

1. 读取旧 `TASK.md`、`PROGRESS.md` 及必要的架构/API 文档，先确认当前范围、状态和验收事实。旧记录矛盾或缺乏证据时写明待校准，不能仅因历史状态为 DONE 就补勾验收。
2. 迁移前检查 Git 跟踪状态与是否包含私有信息。沿用全局私有信息约定，不把旧文档中的真实凭证搬进可提交正文或共享备份。
3. 将当前目标、状态、验收与必要结果合并进 `TASK.md`。保留有用的专项架构/API 文档作为引用，移除复制的项目规范；独有的有效约定归入项目规范，不能直接丢弃。
4. 旧 `PROGRESS.md` 等被取代文件中，有价值的历史并入任务记录的历史段落；长篇历史可保留为明确标注的只读历史附录，不再维护另一份当前状态。核对信息和引用后删除已被完整替代的文件；不要批量清空未知附件或文档。
5. 任务集保留子任务关系、依赖和集成记录，删除重复的子任务状态、范围和批次状态。索引保留必要链接与独有上下文，移除复制的状态和旧操作流程。
6. 检查迁移前后关键事实、链接、依赖与验收均保留，重复执行不再产生副本或新增迁移日志。只总结实际完成的迁移和待校准事项，不为了套模板创造缺失事实。

旧版强制补齐四文档的迁移脚本与格式校验器已经移除。迁移按语义合并；校验按 skill 的检查原则执行，不再要求旧表格结构。
