# 禅道工作流

复用当前会话中可用的 `zentao_*` 工具，按用户意图读取禅道上下文或修复业务代码。连接名称由客户端决定，不绑定某个 MCP server ID。

## 连接与资料

- 禅道地址、认证与环境变量由用户在宿主原生 MCP 界面配置。本 skill 不注册或启动第二个 MCP，不导入凭证，也不另建私有配置文件。
- 先确认所需工具在当前会话可用；不可用时说明缺少的工具，请用户检查界面中的禅道连接并重新连接或新建会话，不以直接 HTTP 请求替代。
- 用 `zentao_get_workflow_guide` 按需加载服务提供的指南，避免复制 API catalog 或工具契约。Bug 修复读取 `workflow-bugfix`、`mcp-tools` 与 `api-bugs`；附件处理读取 `attachments`；陌生 REST 调用读取 `api-catalog`；回写前读取 `write-actions`；失败时读取 `failure-handling`。
- 配置、认证或写操作开关不明确时，再调用 `zentao_health_check`；不要在报告中展示连接凭证。

## 按意图处理

1. 只提供 Bug 编号，或要求查看、分析、定位时，只读取与分析，不修改业务代码或禅道状态。明确要求修复才实施。
2. 有 Bug 编号时用 `zentao_get_bug` 读取详情，结合摘要与原始响应确认复现步骤、预期、实际表现和关联对象。查询“我的 Bug”或“指派给我的 Bug”时用 `zentao_list_my_work`；明确指定产品、项目或执行范围时用 `zentao_list_bugs`。
3. 有相关图片、截图、附件或 `fileID` 时，先下载并实际查看再下结论。使用 `zentao_download_file`，附件保存在业务仓库外，按工具返回的本地路径或下载链接查看；不把客户附件或原始日志放进仓库。
4. 修复前确认目标业务仓库，读取其适用指令与规范。按 Bug 证据定位根因、修改和验证；不因使用本 skill 自动创建 `.task`、切换分支或提交代码。
5. 修复代码不等于授权回写禅道。评论、指派、解决、关闭或其他状态修改需要对应的明确授权；回写前按服务指南准备 dry-run，核对目标与内容后再执行。服务端写开关开启也不扩大用户授权；接口缺失或写入被拒绝时说明事实，不绕过到 legacy 接口。

交付时说明 Bug 编号、分析结论或实际改动、验证结果和未完成事项；附件只引用必要证据与仓库外路径。
